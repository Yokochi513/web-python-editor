# 0010. 実行状態はツールバーのステータス表示で示す

## ステータス

採用（2026-09-15）

## コンテキスト

[基本設計 §3](../design.md) の実行フローでは、UI が次の状態をとる。

| 状態 | 発生源 |
| --- | --- |
| 初期化中 | パネルを開いた直後（`ready` 未受信） |
| 実行可能 | `ready` 受信後 |
| 実行中 | `run` 送信後 |
| 初期化失敗 | `initError` 受信 |
| 再初期化中 | 停止（`terminate()`）直後 |

**このうち「初期化中」「再初期化中」「初期化失敗」は、ボタンの活性だけでは区別がつかない。** いずれも実行ボタンが無効という点で同じ見え方になるが、待てば解決するのか、待っても解決しないのかが異なる。Pyodide の初期化は数秒単位のコストがかかるため（[ADR 0004](0004-use-pyodide-as-python-runtime.md)）、無効なボタンを前に理由もわからず待たされる状態は避けなければならない。

提示方法の候補は次のとおり。

- **ボタンの活性のみ**: 追加の領域を使わないが、上記のとおり状態を区別できない。
- **トースト／一時的な通知**: 目を引くが、消えたあとは状態が読み取れない。初期化中のような**継続する状態**とは相性が悪い。
- **出力領域に書く**: 状態と実行結果が同じ場所に混ざる。クリアすると状態表示も消える。
- **ツールバーに常時表示する**: 状態が常に読み取れる。ただしサイドパネルは幅が狭く（[ADR 0006](0006-use-side-panel-as-editor-surface.md)）、ツールバーの横幅をボタンと分け合うことになる。

## 決定

実行状態はツールバー左端のステータス表示（インジケータ + 短いラベル）で常時示す。

- 状態インジケータ（8px の円）とラベルを横に並べ、ツールバーの左端に置く
- ボタン（実行 / 停止）はツールバーの右端に置き、ステータスとは反対側に寄せる
- 色は状態の性質で分ける — 進行中は `status/running`、正常は `status/success`、失敗は `status/error`
- ラベルは日本語の短文とし、折り返さない長さに収める（例: `Pyodide を初期化中…` / `準備完了` / `実行中…`）

ボタンの活性はステータスの**代わりではなく併用**する。ステータスが状態を説明し、ボタンの活性がその時点で可能な操作を示す。

## 影響

- ツールバーの高さは 44px とし、ステータスとボタンを同じ行に収める。ステータスに独立した行を与えない（縦方向はエディタと出力領域に譲る）。
- ラベルが伸びるとボタンを押し出すため、**ステータス文言は表示幅の制約を受ける**。文言を追加・変更する際は 400px 幅で折り返さないことを確認する。
- 状態を追加する場合、ステータスの色と文言を定めたうえで [ADR 0008](0008-manage-screen-design-in-figma.md) の Figma ファイルにアートボードを追加する。
- 状態は UI 側が保持する。Worker から届くのは `ready` / `done` / `error` / `initError` といった**出来事**であり（[基本設計 §4](../design.md)）、状態そのものではない。UI がこれらを受けて状態を遷移させる。
