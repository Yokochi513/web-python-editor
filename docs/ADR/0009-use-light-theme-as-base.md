# 0009. UI の基本配色はライトテーマとする

## ステータス

採用（2026-09-15）

## コンテキスト

エディタの配色を決める必要がある。候補は次のとおり。

- **ダークテーマ**: コードエディタの慣例。VS Code をはじめ多くのエディタが既定とする。
- **ライトテーマ**: Chrome のサイドパネル自体の既定の見た目に馴染む。
- **両方を用意し切り替える**: 利用者の好みに対応できるが、色の定義が 2 倍になり、どちらも中途半端に検証されない状態になりやすい。

本プロジェクトの表示面はサイドパネルであり（[ADR 0006](0006-use-side-panel-as-editor-surface.md)）、**エディタは Web ページのすぐ隣に並んで表示される**。単独のウィンドウを占有する通常のエディタとは置かれ方が異なり、隣接するページやブラウザ UI との明暗差が常に視界に入る。

また現時点では実装コードが存在せず（[README](../../README.md)）、テーマ切り替えは色の定義だけでなく CodeMirror 6 のテーマ拡張の構成にも波及する。構成範囲そのものが未決定である以上（[基本設計 §9](../design.md)）、いま両テーマを抱えるのは早い。

## 決定

UI の基本配色はライトテーマとする。

- サイドパネル全体の地色は白系とし、ブラウザ UI との段差を作らない
- シンタックスハイライトは CodeMirror の One Light 系の色相を前提に設計する
- 標準エラー・例外は赤系（`status/error`）で、標準出力とは配色で区別する

ダークテーマは**採用しないのではなく、現時点では作らない**。

## 影響

- 色の定義は Figma のローカル変数（[ADR 0008](0008-manage-screen-design-in-figma.md)）に 1 モードのみ置く。モードは `Light` と名付け、後からモードを追加できる形にしておく。
- 実装側でも色は CSS カスタムプロパティに集約し、要素のスタイル宣言に生の色値を書かない。テーマ追加時の変更範囲を配色の定義だけに閉じ込めるため。
- `prefers-color-scheme: dark` には現時点で応答しない。OS がダークモードでもライトのまま表示される。
- ダークテーマを追加する場合は新たに ADR を起こす。その際、CodeMirror 6 のテーマ拡張をどう構成するか（[基本設計 §9](../design.md) の未決定事項）と併せて判断する。
