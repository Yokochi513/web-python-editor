# 0011. 実行時エラーと初期化失敗は出力領域にインラインで表示する

## ステータス

採用（2026-09-15）

## コンテキスト

[基本設計 §4](../design.md) では、失敗を伝えるメッセージが 2 種類ある。

- `error` — ユーザコードの実行時例外。`message` と `traceback` を持つ
- `initError` — Pyodide の初期化失敗。`message` を持つ

性質は大きく異なる。`error` は**書いたコードを直せば解決する**もので、繰り返し起きることが前提であり、traceback という長い本文を伴う。`initError` は**ユーザのコードとは無関係**で、Python の実行そのものができない。

提示方法の候補は次のとおり。

- **ダイアログ／アラート**: 操作を止める。実行するたびに例外が出る試行錯誤の最中に閉じる操作を挟むのは、この用途と相容れない。また traceback のような複数行の本文を載せる器としても不向きで、コピーもしづらい。
- **トースト**: 消える。traceback を読み終える前に消えるか、読める長さまで留めると視界を塞ぐ。
- **出力領域にインラインで表示する**: 標準出力と同じ場所に、届いた順に積まれる。print の出力と例外の前後関係がそのまま残り、スクロールで遡れて選択もできる。既存の領域を使うため、幅の狭いサイドパネルに新たな領域を足さずに済む。

`initError` は例外ではないが、**Python の実行結果が得られない理由**を示す点で出力領域の役割に収まる。加えて、初期化失敗時に出力領域は必ず空であり、場所を奪い合うこともない。

## 決定

`error` と `initError` はいずれも出力領域にインラインで表示する。ダイアログとトーストは用いない。

- 本文は等幅フォントで表示し、`traceback` の字下げをそのまま保つ
- エラーは淡い赤の背景（`surface/errorSubtle`）と左端の赤い罫線を持つブロックで囲み、標準出力と視覚的に区切る
- 文字色は `status/error` とし、標準出力（`syntax/plain`）と区別する
- `initError` の場合は、加えて**再試行**ボタンと、編集・保存は継続できる旨の説明を同じブロックの直後に置く

`stderr` も同じ赤系の文字色を用いるが、ブロックでは囲まない。逐次届く出力の一部であり（[基本設計 §3.2](../design.md)）、到着のたびにブロックが分断されるのを避けるため。

## 影響

- 出力領域は stdout / stderr / エラーブロックが混在する。いずれも**届いた順に追記**し、種別ごとに分けたタブや領域は設けない。print と例外の前後関係が読み取れることを優先する。
- エラー表示は「クリア」操作の対象に含める。エラーだけが残り続ける状態を作らない。
- `error` を受信しても Worker は生存しているため、状態は実行可能へ戻す（[ADR 0010](0010-show-run-state-in-toolbar-status.md)）。エラー表示と実行ボタンの活性は独立している。
- `initError` の再試行は Worker を作り直して初期化からやり直す。停止時の処理（[基本設計 §3.3](../design.md)）と同じ経路を使えるため、実装を共有できる。
- traceback は横に長くなりうる。サイドパネルの幅では折り返しか横スクロールの選択が必要になる。**どちらにするかは実装時に決める**（[ADR 0003](0003-use-codemirror6-as-editor.md) のエディタ側の折り返し方針とは独立して判断してよい）。
