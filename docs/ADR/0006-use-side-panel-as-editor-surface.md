# 0006. エディタの表示面としてサイドパネルを採用する

## ステータス

採用（2026-09-15）

## コンテキスト

[ADR 0001](0001-implement-as-chrome-extension.md) で拡張機能として実装することを決めたが、エディタをどの表示面に置くかは未決定だった。候補は次のとおり。

- **ポップアップ**: ツールバーアイコンから即座に開ける。ただし**他所をクリックすると閉じる**。閉じれば Web Worker ごと破棄され（[ADR 0005](0005-run-pyodide-in-web-worker.md)）、10MB 超の Pyodide 初期化を繰り返し支払うことになる。参照しながらコードを書く用途と根本的に相容れない。
- **新規タブ**: 表示領域が広く、状態も保持される。しかし参考ページとエディタが同じタブ領域を奪い合うため、**両方を見るにはタブを切り替え続けるか、ウィンドウを分割して並べ直す必要がある**。
- **サイドパネル**: ブラウザ右側に常駐し、Web ページと並べて表示できる。参考ページを開いたまま、タブ構成を変えずにコードを書ける。表示幅が狭いことが制約になる。
- **独立ウィンドウ**: 自由に配置できるが、ユーザがウィンドウの配置を自分で管理することになり、タブ構成の問題を別の形で持ち込む。

本プロジェクトの想定利用シーンは、**参考となる Web ページを開きながら実装する**ことである。このとき、エディタを開くためにタブ構成を組み替えさせるのは受け入れがたい。表示面はページと共存できることを最優先で選ぶ。

## 決定

エディタの表示面としてサイドパネル（`chrome.sidePanel` API）を採用する。

パネルはタブ単位ではなくグローバルに設定し、タブを切り替えても開いたままになるようにする。

## 影響

- manifest に `"side_panel"` キーと `sidePanel` 権限を追加する。

  ```json
  "permissions": ["sidePanel"],
  "side_panel": { "default_path": "sidepanel.html" }
  ```

- `chrome.sidePanel` API は Chrome 114 以降で提供される。`minimum_chrome_version` を設定し、README にも対応バージョンを明記する。
- パネルを開くにはユーザ操作が必要。ツールバーアイコンのクリックで開くよう `setPanelBehavior({ openPanelOnActionClick: true })` を設定する。
- **表示幅が狭い。** VS Code のようなサイドバー + エディタの横並びレイアウトは成立しない。エディタと出力領域は縦に積む構成を前提とし、ファイルツリーのような常時表示の横並び UI は設計に含めない。この制約は CodeMirror 6 の折り返し設定や行番号表示の判断にも影響する。
- タブ切り替え時にパネルの文書が保持されるか（＝ Web Worker と Pyodide の状態が生き残るか）は、実装時に検証する。文書が再読み込みされる挙動であれば、初期化コストの観点で回避策の検討が必要になる。
- **パネルを閉じると編集中のコードが失われる。** コードの永続化（`chrome.storage` への保存）が必要になる。保存の粒度とタイミングは別途決定する。
