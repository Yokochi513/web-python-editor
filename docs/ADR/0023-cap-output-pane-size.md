# 0023. 出力領域に行数と 1 行の文字数の上限を設ける

## ステータス

採用（2026-09-15）

## コンテキスト

[ADR 0011](0011-show-errors-inline-in-output-pane.md) と [基本設計 §5.2](../design.md) により、`stdout` / `stderr` / エラーは出力領域へ届いた順に追記される。追記を止める条件はどこにも書かれていない。

`while True: print(i)` のようなコードは容易に書ける。むしろ初学者が書きやすい部類である。このとき Worker は `stdout` を送り続け、UI は受け取るたびに DOM のノードを積む。

[ADR 0005](0005-run-pyodide-in-web-worker.md) の Worker 分離は、**この症状を防がない。** 分離が守るのは「ユーザコードが UI スレッドを占有しないこと」であって、出力の蓄積は UI スレッドの DOM で起きる。ノードが数万に達すればパネルの操作は成り立たなくなり、停止ボタンを押すこともできなくなる。**停止できないのは、Worker を分離した目的そのものが失われることを意味する。**

もうひとつ、行の長さの問題がある。`setStdout` の `batched` は行単位で呼ばれるため（[pyodide-worker.md](../module_design/pyodide-worker.md)）、改行を含まない巨大な出力——`print("a" * 10_000_000)` など——は**1 行として**届く。行数では数えられない。

## 決定

出力領域に 2 つの上限を設ける。

| 対象 | 上限 | 超えたとき |
| --- | --- | --- |
| 行数 | 2,000 行 | 古い方から取り除き、先頭に「古い出力を省略しました」を 1 行残す |
| 1 行の文字数 | 10,000 文字 | 切り詰め、末尾に省略の印を付ける |

行数で数えるのは、`appendOutput` の 1 回の呼び出しが 1 行に対応するためである。判定は子要素の数で済み、文字数を積算する必要がない。

2,000 行は、読み返しの用途には十分で、DOM としては軽い範囲に収まる。**上限の値そのものに強い根拠はない。** 必要になれば変える。値を選ぶことより、上限があることの方が効く。

省略した事実を 1 行残すのは、[ADR 0011](0011-show-errors-inline-in-output-pane.md) の「失敗や欠落を黙らせない」姿勢に揃える。**黙って消すと、出力の先頭が本当の先頭だと読めてしまう。**

## 影響

- [基本設計 §5.2](../design.md) に上限を加える。追記の原則は変わらない。取り除くのは表示であって、届いた順という関係ではない。
- [main.md](../module_design/main.md) の `appendOutput` に、追記後の切り詰めが加わる。
- **入力待ちの行は切り詰めの対象から外す。** プロンプトが消えると、何を聞かれているか分からないままキャレットだけが残る（[ADR 0012](0012-implement-stdin-as-terminal-with-jspi.md)）。
- 出力領域の内容は保存しないため（[ADR 0013](0013-persist-code-in-storage-local.md)）、切り詰めが永続化に及ぼす影響はない。
- 上限に達するほどの出力が出ている状況自体は、止める手段（停止ボタン）が生きていれば足りる。**上限は出力を正しくすることではなく、操作を生かし続けることを目的とする。**
