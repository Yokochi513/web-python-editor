# 0002. 実装は素の JavaScript / HTML / CSS で行う

## ステータス

採用（2026-09-15）

## コンテキスト

拡張機能の UI とロジックをどの言語・フレームワークで書くかを決める必要がある。

- **素の JavaScript / HTML / CSS**: 依存が最小で、拡張パッケージのサイズを抑えられる。Manifest V3 の制約（リモートコード実行禁止）とも相性がよい。状態管理や DOM 更新は自前で書くことになる。
- **UI フレームワーク（React / Vue / Svelte 等）**: 画面の状態管理は楽になるが、依存とビルド構成が増え、パッケージサイズも大きくなる。
- **TypeScript**: 型による安全性が得られるが、コンパイル工程が必須になる。

本プロジェクトは「軽量な実行環境」を狙いとしており、UI の構造も主にエディタ・実行ボタン・出力領域と限定的である。フレームワークが解決する問題より、依存の少なさと構成の単純さを優先する。

## 決定

実装は素の JavaScript（ES Modules）、HTML、CSS で行う。UI フレームワークおよび TypeScript は採用しない。

## 影響

- UI の状態管理・DOM 更新は自前で実装する。画面が複雑化してきた場合は、この決定を見直す新しい ADR を起こす。
- 型検査は行わない。必要に応じて JSDoc による型注釈での補完を検討する。
- **ビルド工程が不要になるわけではない。** エディタ基盤の CodeMirror 6（[ADR 0003](0003-use-codemirror6-as-editor.md)）は多数の npm パッケージに分割された ES Modules として配布されており、そのままブラウザに読み込ませることはできない。バンドル方法は別 ADR で決定する。
- ソースコードそのものはトランスパイル不要とし、バンドラの役割は「依存の解決と結合」に限定する。
