# 0028. 画面設計が使うフォントを拡張へ同梱する

## ステータス

採用（2026-09-19）

## コンテキスト

[ADR 0008](0008-manage-screen-design-in-figma.md) は Figma を**実装前に見た目を確定させ、実装後に突き合わせる基準**と位置づけ、ローカル変数を CSS のカスタムプロパティへそのまま写すと定めた。その Figma が使っているフォントは 2 つある。

| 用途 | フォント | 使うウェイト |
| --- | --- | --- |
| UI（ステータス、ボタン、出力領域の説明行） | Noto Sans JP | 400 / 500 / 700 |
| コード（エディタ、行番号、出力の本文） | JetBrains Mono | 400 |

どちらも Chrome に標準では入っていない。`sidepanel.html` を書く段になって、この 2 つをどう用意するかが決まっていないことが分かった。

選択肢は 3 つあった。

- **システムフォントへ落とす**: 依存も容量も増えないが、字形と字幅が環境ごとに変わる。とくに**等幅フォントが変わると行番号とコードの桁が合わなくなり**、Figma のアートボードと突き合わせるという ADR 0008 の役割が成り立たなくなる。Windows / macOS で既定の等幅フォントが違う以上、「基準と一致しているか」を確かめる相手が存在しない。
- **Google Fonts から読む**: Manifest V3 は拡張ページからのリモートコード実行を禁じており、フォントはコードではないため技術的には可能である。しかし**ネットワークが無いと表示が崩れる**。Pyodide を同梱してオフラインで完結させる方針（[ADR 0004](0004-use-pyodide-as-python-runtime.md)）と噛み合わない。
- **拡張へ同梱する**: 容量が増える。

## 決定

両フォントを拡張へ同梱する。`@fontsource` から woff2 を取り、`build.js` が `dist/fonts/` へ配る（[ADR 0027](0027-copy-pyodide-from-node-modules-at-build-time.md) と同じ扱い）。

| ファイル | 容量 |
| --- | --- |
| `noto-sans-jp-japanese-{400,500,700}-normal.woff2` | 約 1.0MB × 3 |
| `noto-sans-jp-latin-{400,500,700}-normal.woff2` | 約 13KB × 3 |
| `jetbrains-mono-latin-400-normal.woff2` | 約 21KB |
| `jetbrains-mono-latin-ext-400-normal.woff2` | 約 7KB |

合計は約 3.1MB。**Pyodide の 13MB に対して 4 分の 1 以下**であり、オフラインで完結させるという既定の方針の中では追加の負担が小さい。

`@fontsource-variable/noto-sans-jp` は採らない。可変フォント版は unicode-range で **120 個のファイルに分割**されており、すべてを配ると静的な 3 ウェイトより総量が大きくなる。ブラウザが必要な分だけ取る仕組みは、ローカルに全部を置く拡張では働かない。

ラテン文字は専用のサブセットを後に宣言して優先させる。日本語サブセットにもラテン文字は含まれるが、**字幅の設計が違う**ためである。

## 影響

- [基本設計 §6](../design.md) のディレクトリ構成に `dist/fonts/` が加わり、[§7](../design.md) のコピー対象にフォントが加わる。
- `style.css` の `@font-face` が `dist/fonts/` を参照する。`dist/sidepanel/style.css` から見て 1 段上になる。
- ウェイトを増やす場合は `build.js` のコピー一覧に足す。**一覧に無いウェイトを CSS で指定すると、ブラウザが合成した偽のボールドになる。** Figma で新しいウェイトを使ったら、ここも合わせる。
- 等幅フォントが固定されるため、行番号とコードの桁が環境によらず一致する。Figma のアートボードと実物を重ねて確かめられる。
