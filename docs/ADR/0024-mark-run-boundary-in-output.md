# 0024. 実行の開始時に出力領域へ区切りの行を入れる

## ステータス

採用（2026-09-15）

## コンテキスト

[ADR 0011](0011-show-errors-inline-in-output-pane.md) は出力領域を追記の場と定め、[ADR 0012](0012-implement-stdin-as-terminal-with-jspi.md) はそこへ入力も混ぜて**1 本の履歴として読める**ことを狙いに置いた。[基本設計 §5.2](../design.md) はこの方針を書いている。

一方で、実行を繰り返したときに前回の結果と今回の結果が地続きになる。同じ `print` が並ぶコードでは、どこからが今回の出力か読めない。[main.md](../module_design/main.md) は「実行開始時に出力領域を消すか」を未決として残し、消す・区切り線を入れる・何もしないの 3 案を挙げていた。

**消す案は、追記の原則と衝突する。** `input()` で対話した履歴も、前回のエラーも、実行のたびに失われる。前回の traceback を見ながら直して実行する、という一番ありそうな流れで、直す根拠が消える。

何もしない案は、境目が読めない問題をそのまま残す。

Figma の画面設計（[基本設計 §5.3](../design.md)）を見ると、出力領域には既に状態を説明する行が置かれている。「実行結果がここに表示されます」（01 / 02 / 09）、「出力を受信中…」（03）、「実行が完了しました」（04）、「実行を停止しました」（07）。**出力領域は結果だけでなく、実行の区切りを語る場として設計されている。**

## 決定

実行の開始時に、出力領域へ**区切りの行を 1 本追記する。** 出力は消さない。

区切りは `appendOutput` の `notice` として出す。既にある「実行を停止しました」「実行が完了しました」と同じ系列の行であり、新しい種別を増やさない。

**出力領域が消えるのは、クリアボタンを押したときだけ**とする。ユーザの操作でのみ消える、という関係を保つ。自動で消える経路を 1 つでも作ると、消えた理由がそのつど分からなくなる。

## 影響

- [基本設計 §3.2](../design.md) の実行フローの手順 1 に、区切りの追記を加える。
- [基本設計 §5.2](../design.md) に、実行の区切りを示す行を追記することを書く。
- [main.md](../module_design/main.md) の `handleRunClick` から「出力領域は自動で消さない」の但し書きを外し、区切りの追記を手順に入れる。
- 区切りの見た目（文言、罫線を引くか）は Figma の確定による。アートボード 03 / 04 に区切りを含む状態を足す作業が出る。
- `done` の受信時に「実行が完了しました」を追記する処理も併せて [main.md](../module_design/main.md) へ入れる。Figma のアートボード 04 が示しているが、`handleWorkerMessage` の表に無かった。
