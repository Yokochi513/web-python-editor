# 0019. 保存のフラッシュ契機は `visibilitychange` の hidden のみとする

## ステータス

採用（2026-09-15）

## コンテキスト

[ADR 0013](0013-persist-code-in-storage-local.md) で編集中のコードを `chrome.storage.local` へ自動保存すると決め、[基本設計 §2.2](../design.md) は契機を「入力停止から 500ms のデバウンスを主とし、実行時とパネルを閉じる直前（`pagehide` / `visibilitychange`）のフラッシュを従として併せる」と定めた。

この 2 つのイベントがサイドパネルの文書で実際に発火するかは確認していなかった（[main.md](../module_design/main.md) の未決事項）。併せて [基本設計 §9](../design.md) は「タブ切り替え時にサイドパネルの文書が保持されるか」を検証項目として残していた。保持されないなら Pyodide の初期化コストを切り替えのたびに払うことになる。

使い捨ての拡張（`spike/lifecycle-check/`）で実機を確かめた。

| 操作 | 発火したイベント | 文書 |
| --- | --- | --- |
| タブの切り替え | `visibilitychange`（hidden → visible） | **保持される。** 4 分 15 秒 hidden のままでも同じ文書が復帰した |
| サイドパネルを閉じる | `visibilitychange`（hidden）のみ | **破棄される。** 開き直すと新しい文書になる |
| 拡張のリロード | `visibilitychange`（hidden）のみ | 破棄される |

分かったことは 3 つ。

1. **`pagehide` は一度も発火しなかった。** 文書が破棄された 3 回すべてで記録がない。同じ形で書いた `visibilitychange` のハンドラは、パネルを閉じた瞬間の hidden まで記録できている。**非同期の `storage.set` が間に合わなかったのではなく、発火していない。** `freeze` / `resume` も出ない。
2. **タブの切り替えでは文書が破棄されない。** [基本設計 §9](../design.md) の検証項目の答えである。切り替えのたびに Pyodide を初期化し直す心配はない。
3. **タブの切り替えとパネルを閉じる操作は、`visibilitychange` の hidden では区別できない。** どちらも同じイベントが 1 件出るだけである。

3 が効く。**「閉じる直前だけフラッシュする」ことはできない。** 閉じたことを知る手段がないためである。

## 決定

保存のフラッシュ契機は **`visibilitychange` で `hidden` になったとき**のみとする。`pagehide` は使わない。

hidden になるたびに書くため、**タブを切り替えただけでも保存が走る。** これは無駄だが害はない。一方、区別を試みて書かない条件を設ければ、パネルを閉じた際の編集内容を取りこぼす。取りこぼしと無駄な書き込みでは前者がはるかに重い。保存するレコードは 1 件であり、書き込みの頻度が問題になる規模ではない。

実行時のフラッシュ（[ADR 0013](0013-persist-code-in-storage-local.md)）は従来どおり残す。

## 影響

- [基本設計 §2.2](../design.md) の保存の契機を書き換える。`pagehide` を挙げない。
- `main.js` は `pagehide` のリスナを登録しない（[main.md](../module_design/main.md)）。
- **`visibilitychange` の hidden で非同期の `storage.set` が完了することは実測で確認済み。** パネルを閉じた瞬間の hidden が記録に残っている。
- [基本設計 §9](../design.md) の検証項目「タブ切り替え時にサイドパネルの文書が保持されるか」は解消する。**保持される。**
- **サイドパネルを閉じると文書は破棄される。** 開き直した時点で Worker も作り直され、Pyodide の初期化を再び待つ。[基本設計 §3.1](../design.md) の「初期化の完了を待たずにエディタを表示する」は、タブの切り替えではなく**パネルの開閉のたびに**効く。
- 出力領域の内容を保存しない判断（[ADR 0013](0013-persist-code-in-storage-local.md)）は変わらない。「開き直した時点で Worker は作り直されている」という前提が実測で裏づけられた。
