# 0026. 実行中もエディタは編集可能とする

## ステータス

採用（2026-09-15）

## コンテキスト

[基本設計 §3.2](../design.md) の実行フローはボタンの活性しか定めておらず、実行中にエディタを触れるかを書いていない。[editor.md](../module_design/editor.md) はこれを未決として残していた。

読み取り専用にする理由はある。実行中に編集できると、**画面に表示されているコードと実行中のコードが食い違う。** traceback の行番号が、いま見えている行を指さなくなる。

一方で、読み取り専用にする代償も小さくない。停止は Worker の破棄でしか実現できず（[基本設計 §3.3](../design.md)）、破棄すれば Pyodide の状態は失われる。長い実行の間に次のコードを書けないということは、**書くために実行を捨てるか、実行が終わるまで待つかの二択**になる。無限ループに入ったコードでは前者しかない。

食い違いの方は、実は実行中に限った話ではない。`run` を送った時点でコードは Worker へ渡っており、以降 Worker が持つのはそのスナップショットである。同じ食い違いは [ADR 0013](0013-persist-code-in-storage-local.md) の後勝ちでも起きる。**スナップショットと現在の文書がずれることは、この設計に既に織り込まれている。**

[ADR 0010](0010-show-run-state-in-toolbar-status.md) は「ボタンの活性がその時点で可能な操作を示す」と定めた。この基準に照らすと、編集は実行中であっても可能な操作である。実行を妨げず、実行に妨げられもしない。

## 決定

実行中・入力待ちの間も、エディタは**編集可能なまま**とする。読み取り専用にしない。

[基本設計 §3.1](../design.md) が「初期化の完了を待たずにエディタは編集可能」と定めているのと同じ扱いを、実行中にも及ぼす。**エディタが編集できない状態を作らない**という一貫した形になる。

構文チェックは実行中・入力待ちの間は行わない（[基本設計 §3.4](../design.md)）。この間の編集に対して検査の契機は来ないが、**既に表示されている下線は消さずに残す。** 編集で下線の位置がずれることは CodeMirror 側が追従させる（[editor.md](../module_design/editor.md)）。

保存は実行中も従来どおり行う。入力停止から 500ms のデバウンスは検査と契機を共有するが、**保存はどの状態でも行う**（[main.md](../module_design/main.md) の `onIdle`）。

## 影響

- [基本設計 §3.2](../design.md) に、実行中もエディタは編集可能であることを書く。
- [editor.md](../module_design/editor.md) は `EditorState.readOnly` / `EditorView.editable` を扱わない。**状態によって切り替える経路を作らない。**
- 実行中の編集は次の実行から反映される。実行中のコードは `run` を送った時点のもので、`error` の traceback が指す行番号もそれに対応する。
- 出力領域に実行の区切りが入るため（[ADR 0024](0024-mark-run-boundary-in-output.md)）、どの実行の結果かは履歴から辿れる。編集で見た目が変わっても、出力の側に手がかりが残る。
