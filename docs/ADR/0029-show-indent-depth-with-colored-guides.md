# 0029. インデントの深さを、色の変わる縦線で示す

## ステータス

採用（2026-09-19）

## コンテキスト

[ADR 0014](0014-compose-codemirror-extensions-explicitly.md) は CodeMirror 6 の拡張を明示的に並べると決め、[基本設計 §2.2](../design.md) が含めるものと含めないものを列挙した。**インデントガイドはそのどちらにも挙がっていない。** 検討の対象になっていなかった。

実機で書いてみて、**インデントが深いとどの段にいるのか読めない**ことが分かった。Python はブロックをインデントだけで表すため、この読みにくさが構文の理解に直結する。`if` の中の `for` の中の `if` まで来ると、行頭の空白を数えるしかない。

ガターの行番号は行の位置を示すが、深さは示さない。ハイライト（[ADR 0009](0009-use-light-theme-as-base.md)）も語の種類を示すだけで、構造は示さない。**いま画面にあるもののうち、深さを語るものが 1 つも無い。**

## 決定

インデント 1 段ごとに **1px の縦線**を引き、**段ごとに色を変える**。色は 4 色を巡回する。

色は Figma のローカル変数 `indent/1`〜`indent/4` として定義する（[ADR 0008](0008-manage-screen-design-in-figma.md)）。`syntax/*` の色相を引き継ぎつつ、文字より十分に淡くして地の装飾に留める。

| トークン | 値 | 由来 |
| --- | --- | --- |
| `indent/1` | `#a9c3f2` | `syntax/function` 寄りの青 |
| `indent/2` | `#9fc99e` | `syntax/string` 寄りの緑 |
| `indent/3` | `#dcbd85` | `syntax/number` 寄りの橙 |
| `indent/4` | `#cfa8ce` | `syntax/keyword` 寄りの紫 |

検討した案は次のとおり。

- **単色の縦線**（VS Code 既定相当）: `@replit/codemirror-indentation-markers` で済む。ただし**深さを知るには線を数える**ことになり、元の問題が半分しか解けない。
- **深さごとに背景を薄く塗る**（`indent-rainbow` 本家の方式）: 深さは最も読みやすいが、**幅 400px のサイドパネル**（[ADR 0006](0006-use-side-panel-as-editor-surface.md)）では色の面積が大きく、コードそのものより帯が目立つ。
- **何もしない**: 現状。

縦線と色分けを組み合わせるのは、**色で段を読ませつつ、塗る面積を 1px に抑える**ためである。狭い画面では面積が効く。

## 影響

- [基本設計 §2.2](../design.md) の「含める」へインデントガイドを加える。
- **自前で実装する。** `@replit/codemirror-indentation-markers` は色を 1 色しか持てず、段ごとの色分けができない。依存を増やしたうえで目的を果たせないため採らない。
- 実装は `ViewPlugin` と `Decoration.line` による。行の背景として線を重ね、位置は 1 文字幅から求める。**色の値は JS に持たず、`var(--indent-1)` のように CSS カスタムプロパティを参照する。** Figma から写した値の置き場を `style.css` 1 箇所に保つ（[ADR 0008](0008-manage-screen-design-in-figma.md)）。
- **`.cm-line` の左パディングを 0 にする。** CodeMirror の既定は 6px で、背景の原点と文字の原点がずれていると線が桁に乗らない。キャレットの余地は `.cm-content` 側の padding が持つ。
- 空行の深さは**前後の非空行のうち浅い方**に合わせる。深い方に合わせると、ブロックが終わった後の空行にまで線が伸びる。
- アートボードはこのガイドを描いていない。コード見本のインデントが 1 段しかなく、示せる段が足りないためである。段を増やすために見本を書き換えるほどの利得はない。
