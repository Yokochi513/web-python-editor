# 0022. 貼り付けられた複数行は入力のキューとして扱う

## ステータス

採用（2026-09-15）

## コンテキスト

[ADR 0012](0012-implement-stdin-as-terminal-with-jspi.md) は出力領域を入力面とすると決め、[基本設計 §3.2](../design.md) の入力待ちは「ユーザが 1 行入力して確定する」と定めている。1 回の `stdin` に対して 1 行を返す前提である。

入力面の実機確認（`spike/input-surface/`）で、この前提が貼り付けによって崩れることが分かった。`contenteditable` な入力行へ複数行を貼り付けると**改行がそのまま入る**。

```
貼り付け  案 B / "こんにちは\r\nこんにちは\r\nこんにちは\r\nこんにちは\r\n"
確定      案 B / "こんにちは\nこんにちは\nこんにちは\nこんにちは\n\n"
```

改行を含んだ 1 つの文字列が `stdinResult` として送られ、`input()` が改行入りの値を返すことになる。**`input()` の返り値に改行が含まれないことは Python の約束**であり、これを破ると後続の処理（`int()` への変換など）が意図しない形で壊れる。

扱いは 3 通りある。

- **改行を落として 1 行に潰す** — 安全だが、貼り付けた内容を黙って変える。
- **先頭行だけ採り、残りを捨てる** — 捨てたことがユーザに見えない。
- **ターミナルと同じに扱う** — 改行を入力の確定として解釈し、余った行は次の `input()` へ回す。

本拡張の対象は「参考ページを開いたまま Python を書く」場面であり（[基本設計 §1](../design.md)）、**入力例を丸ごと貼る**のは実際に起こる使い方である。複数行を読むコードを書いて、例を貼って動かす、という流れが 1 行ずつの手入力に落ちるのは不便が大きい。

## 決定

貼り付けられたテキストは**改行を入力の確定として解釈する。** ターミナルの挙動に合わせる。

1. 貼り付けたテキストの CRLF を LF に正規化し、LF で分割する
2. 末尾が改行で終わっている行はすべて確定として扱う
3. 改行で終わっていない最後の行は、確定せず入力行に残す（続きを打てる）
4. いま待っている `input()` が先頭の行を受け取り、**残りはキューへ積む**
5. 次の `stdin` が届いたとき、キューが空でなければユーザの操作を待たずに先頭を取り出して返す

キューから消費した行も、手で打った行と同じく `input` として出力領域に残す。**画面に出ないまま値が渡ると、履歴を読んでも何が入力されたか分からない。**

キューは実行の終了（`done` / `error`）と停止で捨てる。**実行をまたいで残ると、次の実行が身に覚えのない値で進む。**

## 影響

- [基本設計 §3.2](../design.md) の入力待ちの手順 3 に、貼り付けで複数行が一度に確定し得ることと、キューが残っている間は 2 と 3 が省かれることを加える。
- [main.md](../module_design/main.md) に状態 `stdinQueue: string[]` が増える。`beginStdin` はプロンプトを出す前にキューを見る。
- 入力面は案 B（入力待ちの間だけ末尾行の `span` を `contenteditable` にする）を採るため、貼り付けの横取りは `beforeinput` の `insertFromPaste` で行う。**素のまま入れさせない。**
- 1 行だけを貼った場合の挙動は変わらない。末尾に改行がなければ入力行に入るだけである。
- キューが尽きる前に実行が終わった場合、余った行は黙って捨てられる。これを通知はしない。**プログラムが読まなかった入力に意味はなく、通知すると正常な経路で警告が出ることになる。**
