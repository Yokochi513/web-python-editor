# 0008. 画面設計は Figma で管理する

## ステータス

採用（2026-09-15）

## コンテキスト

[基本設計 §5](../design.md) の画面レイアウトは、ツールバー・エディタ・出力領域を縦に積むという**構造**を ASCII 図で示しているにすぎない。実装に入るには、これに加えて次を確定させる必要がある。

- 各要素の寸法・余白・配色といった具体的な値
- [§3](../design.md) の実行フローで UI がとる**状態**（初期化中／実行可能／実行中／正常終了／実行時エラー／初期化失敗／停止直後）が、それぞれどう見えるか

これらを Markdown の文章と ASCII 図だけで表現するには限界がある。状態ごとの差分はボタンの活性・ステータス文言・出力領域の中身という細かな違いの集合であり、文章に落とすと読み手が頭の中で再構成することになる。

一方、画面設計をどこに置いても、実装のソースは HTML / CSS である（[ADR 0002](0002-use-vanilla-js-html-css.md)）。デザインツールからコードを生成するわけではないため、ツールに求めるのは**実装前に見た目と状態を確定させ、実装後に突き合わせる基準**としての役割に限られる。

## 決定

画面設計は Figma のデザインファイルで管理する。

- ファイル: [web-python-editor 画面設計](https://www.figma.com/design/g4H9KOklj4zVd8oQMUbb0g)
- 粒度は**状態ごとに 1 アートボード**とし、[§3](../design.md) の実行フローおよび [§4](../design.md) のメッセージ仕様と対応づける
- 配色・余白・角丸は Figma の**ローカル変数**（`Design Tokens` コレクション）として定義し、アートボードから直接色を指定しない

Figma はあくまで**見た目の基準**であり、決定そのものではない。画面に関する決定は本 ADR 群に記録し、Figma はその結果を可視化したものとして扱う。

## 影響

- 画面に関わる決定を変える場合、ADR を起こしたうえで Figma ファイルを更新する。**Figma を先に書き換えて決定の記録を省略しない。**
- Figma のローカル変数が CSS のカスタムプロパティに対応する。実装時は変数名をそのまま CSS 変数名に写し、値の二重管理を避ける。
- Figma はリポジトリの外にあるため、バージョン管理が Git と分離する。リポジトリ側からは URL で参照するにとどめ、画面のスクリーンショットをリポジトリに取り込んで同期させることはしない。
- 状態を追加・変更した場合、対応するアートボードの追加が必要になる。アートボード名は `NN 状態名 (英語名)` の形式で、[§4](../design.md) のメッセージ種別と読み合わせられるようにする。
