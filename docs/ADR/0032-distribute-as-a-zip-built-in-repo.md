# 0032. 配布物は `dist/` の ZIP とし、組み立ても自前で行う

## ステータス

採用（2026-09-19）

## コンテキスト

実装と自動テストが揃い、残るのは配布の形だけになった。Chrome ウェブストアへ出すには次が要る。

- 拡張一式を収めた **ZIP を 1 つ**。展開したとき `manifest.json` が最上位に来ること
- 登録内容（説明、権限の正当化、データの取り扱いの申告）
- ライセンス

`dist/` は既にそのまま拡張として読み込める形になっている（[ADR 0007](0007-use-esbuild-as-bundler.md)）。ZIP にするだけで配布物になる。

## 決定

### 配布物は `dist/` を固めた ZIP

`npm run package` で `release/web-python-editor-<version>.zip` を作る。フォルダで包まず、`dist/` の中身を直接入れる。

### ZIP の組み立ては自前で行う

`archiver` のようなパッケージを入れない。**ZIP は固定長のヘッダと中央ディレクトリだけの形式**で、圧縮（deflate）と CRC32 は `node:zlib` が持っている。[ADR 0031](0031-write-tests-with-node-test-runner.md) でテストランナーに依存を足さなかったのと同じ判断による。

**ただし、書いた ZIP を読み直して確かめる工程を必ず通す。** 自前で組み立てる以上、「作れた」ことは「読める」ことを意味しない。実際、最初の実装は**中央ディレクトリの位置を 2 バイトずれた欄へ書いており**、展開すると 0 ファイルになった。ヘッダの目印だけでなく、各エントリを展開して CRC32 が一致するところまで見る。位置がずれていればヘッダは合っていても別のバイト列を指す。

### ライセンスは MIT

`package.json` の `ISC` は `npm init` の既定値が残っていたもので、意図した選択ではなかった。依存している CodeMirror・Pyodide・fontsource もいずれも MIT 系で、矛盾しない。`LICENSE` を置く。

### 固める前に必ずビルドし直す

`npm run package` はビルドを挟む。`build.js` は `dist/` を消してから作り直すため、テストが残した一時ファイルが確実に消える。

テストは Worker を Node で動かすために `dist/worker/` へ写しを置く（[ADR 0031](0031-write-tests-with-node-test-runner.md)）。**`npm test` の直後に固めたところ、それが配布物へ混ざった。** 名前が `_` で始まるものを `package.js` 側でも弾き、二重に塞ぐ。

### 登録内容は `docs/store-listing.md` を原本とする

ストアの入力欄へ直接書かず、リポジトリの側に原本を置いて写す。**入力欄は履歴が残らず、次のバージョンで何をどう書いたか追えない。** 権限の正当化やデータの取り扱いの申告は、書いた内容と実装が食い違うと審査で問題になる部分であり、実装と同じ場所で管理する。

## 影響

- [基本設計 §6](../design.md) に `package.js` と `release/` が加わる。`release/` は生成物なので Git から外す。
- **「外部と通信しない」と申告する。** 自前のコードに通信 API（`fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon`）を含まず、`host_permissions` も要求していないことを確かめたうえでの申告である。Pyodide の読み込みは `chrome-extension://` の自分自身に対するもので、外部へは出ない。**この前提を崩す変更を入れるときは、`docs/store-listing.md` の申告も同時に直す。**
- バージョンは `manifest.json` と `package.json` の両方に持つ。**Chrome ウェブストアはバージョンを下げられない**ため、上げる前に確認する。
- スクリーンショットは用意していない。実際に動いている画面を撮るのが最も正確で、実機の画像が要る。
