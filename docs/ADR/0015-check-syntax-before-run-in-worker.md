# 0015. 構文エラーは実行前に Worker の `compile()` で検出し、エディタ内に表示する

## ステータス

採用（2026-09-15）

## コンテキスト

[ADR 0014](0014-compose-codemirror-extensions-explicitly.md) では lint を含めなかったが、**構文エラーは実行してから気づくのでは遅い**という判断に至った。実行するまで分からないということは、書き終えて実行ボタンを押し、出力領域の traceback を読んで初めてタイプミスを知るということであり、思いついたコードをすぐ試す用途では往復が 1 回無駄になる。

診断の情報源の候補は 3 つ。

- **Lezer の構文木のエラーノードを拾う**: UI スレッドだけで完結し、Pyodide の初期化を待たずに即座に出せる。ただし Lezer のパーサはエラー回復を行うため、**検出結果が Python 実際の `SyntaxError` と一致しない**。位置も粗く、`IndentationError` のような Python 固有の規則は扱えない。
- **Worker で `compile(code, "<editor>", "exec")` を呼ぶ**: **実行せずに**構文検査だけを行える。CPython そのものの判定であるため、実行時に出るエラーと食い違わない。行・桁・メッセージがそのまま得られる。代償として Pyodide の初期化完了を待つ必要があり、Worker が塞がっている間は答えが得られない。
- **pyflakes 等を同梱する**: 未使用変数や未定義名まで拾えるが、サードパーティの Python パッケージは同梱しないという方針に反する（[ADR 0004](0004-use-pyodide-as-python-runtime.md)）。

表示方法も論点になる。lint の標準的な提示は下線＋ツールチップだが、CodeMirror には `lintGutter` もある。後者はガターをもう 1 列消費し、折りたたみを落とした判断（[ADR 0014](0014-compose-codemirror-extensions-explicitly.md)）と噛み合わない。

## 決定

`@codemirror/lint` を構成に加える。診断の情報源は **Worker の `compile()`** とする。

- 検査の契機は**入力停止から 500ms のデバウンス**とし、**コードの自動保存（[ADR 0013](0013-persist-code-in-storage-local.md)）と同じ契機に乗せる**。入力が止まった一点で「保存する」「構文を見る」を揃え、契機を二重に持たない。
- 表示は**下線とツールチップのみ**とし、`lintGutter` は使わない。文字色・下線には既存の `status/error` トークンを用いる。
- **実行ボタンの活性には影響させない。** 構文エラーがあっても実行は妨げない。
- Pyodide の**初期化完了前**、および**実行中・入力待ちの間**は検査を行わない。

`compile()` は実行を伴わないため、検査のために副作用が起きることはない。ただし **CPython は最初の構文エラーで解析を止める**ため、一度に得られる診断は最大 1 件である。

実行ボタンの活性を構文エラーに連動させないのは、検査結果が Worker からの応答として**遅れて届く**ためである。連動させると、入力の合間にボタンが押せたり押せなくなったりする。ボタンの活性はその時点で可能な操作を示すものであり（[ADR 0010](0010-show-run-state-in-toolbar-status.md)）、コードの正しさを示すものではない。

## 影響

- メッセージ仕様に往復を 1 組追加する（[基本設計 §4](../design.md)）。UI → Worker の `check`、Worker → UI の `checkResult`。`run` と同様に識別子を持たせ、遅れて届いた結果を破棄できるようにする。
- **エラーの表示場所が 2 つに分かれる。** 実行前の構文エラーは**エディタ内**（本 ADR）、実行して得られた例外と初期化失敗は**出力領域**（[ADR 0011](0011-show-errors-inline-in-output-pane.md)）。前者は「まだ実行していない」、後者は「実行した結果」を示す。この境界は動かさない。
- **初期化が終わるまで構文エラーは出ない。** パネルを開いた直後に編集を始めた場合、数秒間は下線が付かない。Lezer の構文木を暫定の情報源にする案は採らなかったため、この空白は受け入れる。
- **実行中と入力待ちの間も検査は止まる。** その間、既に表示されている下線は消さずに残す。消すと「直った」と読めてしまうため。
- 停止（`terminate()`）で Worker を作り直す間も検査はできない。再初期化の完了後、次のデバウンスで復帰する。
- Figma にアートボード「09 構文エラー」を追加する（[ADR 0008](0008-manage-screen-design-in-figma.md)）。実行状態の一覧ではなくエディタ内の表示を示すアートボードとなるため、ツールバーは「02 実行可能」と同じになる。

### 実装時に決めること

- `compile()` の呼び出しを Pyodide の Python 側で行うか、JS 側から `pyodide.runPython` で包むか
- `SyntaxError` の `offset` を CodeMirror の文書位置へ変換する際の桁の扱い（CPython は 1 起点）
- ツールチップの文面に Python のメッセージをそのまま出すか、整形するか
