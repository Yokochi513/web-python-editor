# 0031. 自動テストは `node:test` で書き、DOM を要さない範囲に限る

## ステータス

採用（2026-09-19）

## コンテキスト

実装が一巡し、実機で一通りの経路を確認した。しかし**退行を捕まえる仕組みが無い。** 実装中の検証はその場限りのハーネスで行い、残していない。

残さなかったものの中に、実際にバグを見つけたものがある。Worker をヘッドレスで叩くハーネスは、**JS の `null` を Pyodide が `jsnull` へ写すために EOF が成立していなかった**ことを見つけた（[ADR 0021](0021-represent-eof-as-null-stdin-result.md) / [pyodide-worker.md](../module_design/pyodide-worker.md)）。設計書どおりに書いたコードが動いていなかったという類の失敗であり、読み返しでは見つからない。

## 決定

### ランナーは Node 同梱の `node:test`

依存を増やさない。[ADR 0002](0002-use-vanilla-js-html-css.md) は素の JavaScript、[ADR 0007](0007-use-esbuild-as-bundler.md) はビルドの役割を結合とコピーに限ると決めており、テストのためだけに Vitest や Jest を入れるのは方針に合わない。`node --test` で足りる。

### 対象は DOM を要さない範囲に限る

| 対象 | やり方 |
| --- | --- |
| `protocol.js` | 期待値を基本設計 §4 の表から写して突き合わせる |
| `editor.js` | `state` と `dispatch` だけを持つ偽の `view` を渡し、公開 API のまま試す |
| `pyodide-worker.js` | ビルド済みの `dist/` を**本物の Pyodide**で動かす |

**`main.js` は対象外とする。** DOM と `chrome.*` の両方が要る。jsdom を入れれば形は作れるが、入力面が依存しているのは IME の合成イベント・`contenteditable` の挙動・貼り付けといった**ブラウザの実装そのもの**であり（[main.md](../module_design/main.md) の入力面の節）、jsdom で通ったことが Chrome で通る保証にならない。偽の安心を買うために依存を増やさない。`main.js` は実機での確認に頼る。

### 期待値は設計書から写し、実装からは作らない

`protocol.js` の 11 個の種別は基本設計 §4 の表を写したものを持つ。実装を参照して期待値を作ると、変えたことに気付けなくなる。

### Worker のテストはビルド済みの `dist/` を使う

Pyodide 一式が隣に揃っているのがそこだけである。`indexURL` の 1 行だけ Node 向けに置き換える（Pyodide の Node 側ローダは `file:` URL を解決できない）。**置き換える対象が見つからなければ失敗させる。** 実装が変わったのに気付かず、別物を試し続ける状態を避ける。

入力待ちの経路は JSPI を要するため `--experimental-wasm-jspi` を付けて走らせる。

## 影響

- [基本設計 §6](../design.md) に `test/` が加わる。
- `npm test` はビルドを挟む。`dist/` が古いまま試すことを防ぐ。
- **テストが退行を捕まえることを、意図的にコードを壊して確かめた。** EOF の判定を元のバグへ戻す、`stdinResult` の綴りを 1 文字変える、`endColumn` の丸めを外す、の 3 つがいずれも検出された。通ることだけを確かめたテストは、何も守っていない可能性がある。
- `main.js` が対象外である範囲は README に明記する。**何を確かめていないかが分からないテストは、確かめたつもりを作る。**
