# 0013. 編集中のコードは `chrome.storage.local` に単一バッファとして自動保存する

## ステータス

採用（2026-09-15）

## コンテキスト

[ADR 0006](0006-use-side-panel-as-editor-surface.md) でサイドパネルを表示面に選んだ結果、**パネルを閉じると文書が破棄され、編集中のコードが失われる**。永続化が必要であることは決まっていたが、その方式は未決定のまま残っていた（[基本設計 §9](../design.md)）。

論点は 3 つの軸に分かれる。

### どこに置くか

- **`chrome.storage.local`**: 約 10MB。非同期。ブラウザを再起動しても残る。エディタ 1 面分のコードに対しては過剰なほど余裕がある。
- **`chrome.storage.sync`**: 同じアカウントの他マシンへ同期される。ただし全体 100KB、**1 項目 8KB**、**書き込み 120 回/分**という制限があり、項目上限と書き込みレートのどちらも自動保存と正面からぶつかる。
- **`chrome.storage.session`**: ブラウザを閉じると消える。目的そのものを満たさない。
- **`localStorage`**: 同期 API であり UI スレッドを止める。`chrome.storage` がある以上、選ぶ理由がない。
- **IndexedDB**: 単一バッファには過剰。複数ファイルや履歴を持つ設計になれば再検討の余地がある。

### いつ書くか

- **編集のたびに即保存**: 取りこぼしはないが、打鍵ごとに書き込みが走る。
- **デバウンス**: 入力が止まってから書く。取りこぼす窓が最後の数百 ms に縮む。
- **閉じる直前にまとめて**: `chrome.storage.set` は非同期であり、**文書の破棄に間に合う保証がない**。単独では方式として成立しない。
- **実行時**: 区切りとしては自然だが、これだけでは実行せずに閉じた場合を救えない。

### 何を 1 単位とするか

- **単一バッファ**: キー 1 つ。複数ファイルからなるプロジェクトを対象外とする方針（[基本設計 §1](../design.md)）と素直に一致する。
- **世代を持つ**: 実行のたびにスナップショットを残せば誤消去から戻せるが、保存レコードと復元 UI の設計が要る。
- **名前付きの複数ドキュメント**: スニペット集として使えるが、切り替え UI の置き場所から設計し直しになる。幅の狭いサイドパネルの縦積み前提（[基本設計 §5](../design.md)）に影響する規模であり、決めるなら独立した ADR になる。

## 決定

編集中のコードは **`chrome.storage.local` に単一のレコードとして自動保存する**。

- **契機はデバウンス 500ms を主とし**、実行時とパネルを閉じる直前（`pagehide` / `visibilitychange`）のフラッシュを従として併せる。閉じる直前のフラッシュは**最善努力**であり、保存の成立をここに依存させない。
- **保存するのはコードと、キャレット位置・スクロール位置**とする。同じレコードに収める。
- **出力領域の内容は保存しない。**
- **複数のウィンドウで同時に開かれた場合は後勝ち**とする。`storage.onChanged` による他パネルへの追従は行わない。

出力を保存しないのは、パネルを開き直した時点で Worker は作り直されており（[基本設計 §3.1](../design.md)）、前回の実行結果だけが残っていると**いまの状態の出力と誤読される**ためである。復元直後の出力領域は常に空になる。

`storage.onChanged` で追従しないのは、追従させると**もう一方のパネルで入力中の内容を上書きしかねない**ためである。後勝ちは編集内容を失いうるが、失う範囲が「後から保存されなかった側」に限られ、挙動が説明可能である。

## 影響

- 追加の権限は不要。`storage` は既に manifest にある（[基本設計 §8](../design.md)）。
- 保存レコードは 1 件。将来フィールドが増えることに備え、レコードにはバージョンを示す欄を持たせる。
- 復元は Pyodide の初期化と独立に行う。エディタは初期化の完了を待たずに表示されるため（[基本設計 §3.1](../design.md)）、復元もそれを待たない。
- **世代を持たないため、全消去してから保存が走った場合に戻す手段はない。** パネルを閉じれば CodeMirror の undo 履歴も失われる。誤消去からの復旧を求めるなら、スナップショットを足す ADR を別に起こす。
- **他マシンへの持ち越しはできない。** `sync` を選ばなかったことの代償であり、必要になれば新しい ADR で判断する。その際は 8KB の項目上限に対する分割と、書き込みレート制限に合わせた契機の設計が論点になる。
- 2 つのウィンドウで同時に編集すると、片方の編集が失われる。これを画面上で警告することはしない。幅の狭いパネルに常時の注意書きを置くより、単一バッファという前提を設計として明示する方を採る。

### 実装時に決めること

- 保存キーの名前
- デバウンス値の最終調整（500ms を出発点とする）
- 選択範囲まで復元するか、キャレット位置だけにするか
